# 하늘땅 급여·연차

엑셀 통합산출을 대신하는 로컬 우선 정적 웹페이지입니다. 서버와 회원가입 없이 브라우저 안에서 받은 XLSX·CSV를 자동 분류·입력하고, 급여 계산, 급여명세서 인쇄/PDF 저장, 인건비·세무사 CSV, 연차 관리, JSON 백업을 제공합니다.

## 실행

가장 간단한 방법은 `index.html`을 더블클릭하는 것입니다. 브라우저 보안 정책 때문에 파일 다운로드나 인쇄가 제한되면 이 폴더에서 다음을 실행합니다.

```bash
python3 -m http.server 4173
```

그 뒤 <http://localhost:4173>을 엽니다. 데이터는 현재 브라우저의 `localStorage`에만 저장됩니다.

처음 사용하는 담당자는 `guide.html`을 열면 실제 메뉴 순서에 맞춘 쉬운 사용 안내를 볼 수 있습니다. 프로그램 오른쪽 위의 `처음 사용 안내 → 그림처럼 자세히 보기`에서도 열 수 있습니다.

## 권장 월 마감 순서

1. `기본 설정`에서 급여월과 지급일을 확인합니다.
2. `자료 가져오기`에 내려받거나 전달받은 XLSX·CSV 파일을 한꺼번에 끌어놓습니다.
3. 자동으로 연결된 직원과 변경값을 미리보고 `선택한 자료 적용`을 누릅니다.
4. `직원 관리`, `이번 달 급여`, `보험·공제`에서 누락 경고가 있는 값만 확인합니다.
5. `검토·마감`의 오류와 주의사항을 모두 확인합니다.
6. `출력·백업`에서 명세서와 CSV를 만들고 JSON 백업 후 마감합니다.

## 자동 가져오기

다음 자료를 파일명과 시트 헤더로 구분합니다. 여러 자료가 한 통합산출 파일에 있어도 현재 급여월 시트만 읽습니다.

- 통합산출 급여표: 직원 고정급여, 시간외, 월 수당, 비과세, 연말정산·기타공제
- 시간외 시트: 별칭별 총 시간과 연차 부여·누적 사용 현황
- 제수당 시트: 근로지원금, 4~5시 근무, 사협 별도지급
- 사회보험 5종: 국민연금, 건강·장기요양, 고용보험, 국민연금·고용보험 두루누리 지원금
- 표준 급여 입력 CSV: `입력용 CSV 양식 받기`로 만든 새 자료

적용 전 모든 변경을 미리 보여주며 이름 또는 별칭을 기존 직원 UUID에 연결합니다. 동명이인과 연결되지 않은 보험 행은 자동 제외되고 담당자가 연결 대상을 선택할 수 있습니다. 급여표의 새 직원은 확인 후 새 UUID로 추가됩니다. 파일에서 감지한 월이 현재 급여월과 다르면 다시 확인합니다.

원본의 주민번호·보험번호·비밀번호 등 매핑하지 않은 열은 상태나 백업에 저장하지 않습니다. 보험 3개 기본 자료(국민연금, 건강·요양, 고용)를 함께 적용하면 최종 공제액과 보험 확인 상태까지 자동 갱신합니다. 자세한 범위와 안전장치는 [AUTOMATION.md](AUTOMATION.md)를 참고하세요.

## 포털 자료 반자동 다운로드

담당자가 로그인만 하면 포털 3곳의 엑셀 5개를 받아 `원본자료/YYYY-MM/`에 검증·저장하는 도구가 `automation/`에 있습니다. 사용법은 [automation/README.md](automation/README.md)를 보세요.

## 테스트

```bash
node tests/payroll.test.js
node tests/portal-paste.test.js
node tests/importers.test.js
```

소득세 자동 계산은 국가법령정보센터의 `소득세법 시행령 별표 2` 중 2026년 2월 27일 개정표를 내장합니다. 공제대상가족 수에는 본인을 포함하고, 8~20세 자녀 수는 별도 입력합니다. 법령 개정 시 표와 테스트를 함께 갱신해야 합니다.

## 여러 담당자가 함께 쓰기 (Cloudflare, 무료)

담당자가 2명 이상이면 정적 파일을 Cloudflare Pages에 올리고, 상태 JSON 한 개를 Workers KV에 저장하는 `functions/api/state.js`를 함께 배포합니다. 접속 제한은 Cloudflare Access(무료, 50명까지)가 맡습니다. 배포 주소에서 열면 앱이 자동으로 공유 서버 자료를 읽고 저장하며, `index.html` 직접 실행이나 localhost에서는 기존처럼 브라우저에만 저장합니다.

1. Cloudflare 대시보드 → Workers & Pages → KV에서 네임스페이스 하나를 만들고 ID를 `wrangler.toml`의 `id`에 넣습니다.
2. Workers & Pages → Create → Pages → 이 GitHub 저장소 연결. 빌드 명령 `sh scripts/build-static.sh`, 출력 폴더 `dist`. KV 바인딩은 `wrangler.toml`이 정합니다.
3. Pages 프로젝트 → Settings → Access policy → Enable. Zero Trust의 해당 애플리케이션에 본 주소(`<프로젝트>.pages.dev`)를 도메인으로 추가하고, 정책 Include를 Emails로 바꿔 담당자 이메일만 넣습니다. 이 단계 전에는 API가 401만 돌려줍니다.
4. 기존 담당자 PC에서 `출력·백업 → JSON 백업`을 받은 뒤 배포 주소에서 `백업 복원`을 하면 그 자료가 공유 서버에 올라갑니다. 다른 담당자는 같은 주소를 열기만 하면 됩니다.

두 사람이 거의 동시에 저장하면 뒤에 저장한 쪽은 거부되고 화면에 안내가 뜹니다. 이때는 JSON 백업을 받아 두고 새로고침해 최신 자료를 받은 뒤 다시 입력합니다. 원본 엑셀은 여전히 각자 PC의 `원본자료/`에서 읽어 올리며 서버에는 계산 결과 상태만 저장됩니다.

API 검증: `node tests/state-api.test.mjs`

## 배포 선택

- 개인정보 보호가 우선이면 담당자 PC에서 로컬 실행하는 구성이 가장 저렴하고 안전합니다.
- 여러 PC에서 접속만 필요하고 데이터 동기화는 필요 없다면 정적 파일을 Cloudflare Pages, GitHub Pages, Netlify 등에 무료 배포할 수 있습니다. 다만 앱 데이터는 각 브라우저에 따로 남습니다.
- 여러 담당자가 같은 데이터를 공유해야 한다면 위 Cloudflare Pages 구성(Access 인증 + KV 저장, 마지막 저장자 기록)을 씁니다. 급여 개인정보이므로 Access 없이 공개 주소에 올리지 마십시오.

원본 파일은 `원본자료/YYYY-MM/`에 급여월별로 보관하며 폴더 전체가 gitignore 대상입니다. 민감정보가 포함되어 있습니다. 저장소를 공개로 전환하거나 정적 호스팅의 배포 대상에 원본 엑셀/PDF/PPTX를 포함하지 마십시오. `app.js`의 기본 시드는 익명 예시 직원입니다. 실제 직원 자료는 JSON 백업 복원이나 자료 가져오기로 넣습니다.
